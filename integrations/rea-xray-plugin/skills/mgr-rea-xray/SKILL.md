## Run decision ladder

1. Read the target repo's `AGENTS.md`, most recent active-branch handoff, tests, architecture, licenses and CI. Search all branches/active PRs before claiming a handoff or feature is absent. Verify exact target, owner authorization and rights; inspect a source snapshot, not live taxpayer records or credentials.
2. Prefer **passive static REA** to map application modules, JavaScript/Electron, binary formats, Ghidra/Hopper metadata, archives, website layout and evidence. Full native catalog provides investigation depth, not permission to execute unknown code or browse private pages. For a URL, research ordinary public pages first; any REA browser CDP attachment requires its explicit origin allowlist and separate permission.
3. When REA is callable, run a version/capability doctor first (`rea mcp doctor --json` if an authorized local CLI is available). Call only the operation relevant to the authorized target. Use `rea analyze-javascript-application <approved-path> --json` on a trusted source checkout; the saved generated evidence is not itself a bug fix. Tool-family scoping (`REA_MCP_TOOL_FAMILIES`) and schema profile (`REA_MCP_INPUT_SCHEMA_PROFILE`) may limit context without creating a second engine.
4. Treat any active process instrumentation, Frida attach/spawn, debugger, APK extraction, browser CDP, credential-bearing HAR, network capture or deployment as a separate risk step. Use only explicitly authorized targets and safe isolated data. Never run unknown executables, break access controls, evade paywalls, exfiltrate taxpayer data, copy restricted proprietary source or claim independent licensing from a public webpage.
5. Cross-check REA findings against direct source, the newest branch/PR and real tests. Classify each finding as OBSERVED, INFERRED, UNKNOWN, NOT EXECUTED or REFUTED. Map to exact source file/line and record REA version, tool/command, elapsed time, evidence ID/hash, scope, exclusions, comparison with `rg`/GitHub source, and what the technique actually uncovered that normal source review did not.
6. Implement original MGR-native fixes in the owning repo, run build/unit/e2e/security/negative tests, keep a rejected/unsupported operation fail-closed, preserve source and history. For tax returns, AI does not authorize sign, file, pay, identity, or tax math; use reviewer decisions and provider/IRS receipts.
7. Append findings, repairs, proofs, skipped work and the next runnable instruction to the **existing handoff** (for Elite Hub currently `docs/current-audit/06-AUDIT-HANDOFF.md` on `audit/elite-hub-20261102`) and its scorecard. Never replace a handoff or create a competing source of truth. Put detailed specialized research in a linked document if necessary.
